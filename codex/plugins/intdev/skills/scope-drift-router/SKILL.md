# Scope drift router

Классифицируй запрос как `same-scope`, `compatible-extension` или `materially-different`. Другой Issue, owner repo, lifecycle, runtime, DB, publication, security или destructive contour — сильный признак materially different; small clarification, acceptance evidence и required fix не разделяй.

Для materially different сначала ищи canonical Issue и reachable Codex task. Native task capabilities проверяй по exact `codex_app__*` names через доступный catalog; на remote host используй real task ID и supported host binding. Не подменяй native task management правкой SQLite, cache или ad-hoc process.

Создавай/обновляй Issue или planning task только при authority на этот external effect. Новый task plan-only до отдельного разрешения implementation. Применяй recursion guard и возвращай existing classification для повторного meta-routing.

Routing не разрешает implementation, publication, deployment или destructive action.
