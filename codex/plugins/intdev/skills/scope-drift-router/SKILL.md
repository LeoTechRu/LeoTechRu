# Scope drift router

Классифицируй запрос как `same-scope`, `compatible-extension` или `materially-different`. Другой work item, owner repository, lifecycle, runtime, data store, publication, security или destructive contour — сильный признак materially different; small clarification, acceptance evidence и required fix не разделяй.

Для materially different сначала ищи work item и reachable task через adapters, настроенные потребителем. Не подменяй native task management правкой внутреннего state store, cache или ad-hoc process.

Создавай или обновляй work item/planning task только при authority на этот external effect. Новый task plan-only до отдельного разрешения implementation. Применяй recursion guard и возвращай existing classification для повторного meta-routing.

Routing не разрешает implementation, publication, deployment или destructive action.
